## Tier 1 — hangs, permanent corruption, broken hard guarantees

### 0a. EXP3 and EXP4 are exactly uniform random under default tuning `[V]`
`bandit/univariate/Exp3Bandit.kt:66` + `:154`, consumed at `:98`;
`bandit/contextual/Exp4Bandit.kt:101` + `:208`, consumed at `:144`; also via
`bandit/BanditFactory.kt:113`.

`defaultEta(K) = sqrt(ln K / K)` and `gamma = (nbrArms * eta).coerceAtMost(1.0)`. But
`K * sqrt(ln K / K) = sqrt(K · ln K)`, which is `>= 1.177` for every `K >= 2`, so **gamma is always
exactly 1.0**. `playDistribution` then computes `(1.0 - gamma) * (w[a]/sumW) + gamma/K`, i.e.
`0 * … + 1/K`. The learned weights are multiplied by zero. Reward learning is entirely disabled in
the default configuration of both policies.

```
K=2 eta=0.5887 gamma=1.0 ... K=100 gamma=1.0
exp3 armWeights after 500 wins for arm0 = [1.0, 0.0, 0.0]    // weights DO learn
exp3 playDistribution = [0.3333, 0.3333, 0.3333]             // and are then discarded
exp3 choose counts   = [1007, 997, 996]
exp4 expertWeights = [1.0, 2.13e-256]  playDistribution = [0.5, 0.5]
```

`gamma = K*eta` is only the correct EXP3 mixing rule when `eta` is the horizon-scaled
`sqrt(ln K / (K T))`; the "horizon-free" collapse to `T = 1` makes it always saturate. Invisible
because `Exp3BanditTest` asserts only on `armWeights()` (which do learn) and its one behavioural
test passes an explicit `gamma = 0.1`. Nothing asserts `playDistribution()` or `choose()` under the
default.

### 0b. `UCB1Normal.evaluate` returns NaN for any arm with a non-zero mean `[V]`
`bandit/univariate/BanditPolicies.kt:217`

```kotlin
val p1 = (mos - nj * snapshot.mean * snapshot.mean) / (nj - 1)
```
`mos` is `meanOfSquares()` = `m2/N + mean²`, i.e. `E[x²]` (`bandit/univariate/Arms.kt:264`), but the
Auer et al. formula subtracts `n·mean²` from the **sum** of squares. Mixing a mean with a sum makes
`p1` strongly negative whenever `mean != 0`, so `sqrt(16 * p1 * …)` is NaN. Checked by hand:
mean=1, n=30 gives `p1 = (1 - 30)/29 = -1`.

```
UCB1Normal arm scores = [NaN, NaN, NaN]
choose counts = [100, 0, 0]        // arm 2 has the best mean
```
`MultiArmedBandit.choose` seeds `bestScore = NEGATIVE_INFINITY` and `NaN > -Inf` is false, so the
policy silently degenerates to "always arm 0". Confirmed untested by design: an `error("PROBE")` in
that branch is hit by exactly one test, whose own comment reads *"mean=0 keeps the
(mos - n*mean^2) variance term non-negative"* — the test was written to route around the bug.

### 1. `DecayingSumStat` livelocks forever on a long half-life `[V]`
`stat/decay/DecayingSumStat.kt:61` with `:73`

`rotationThresholdNanos = weighting.halfLife.inWholeNanoseconds * ROTATION_HALF_LIVES` has no
overflow guard. Above `Long.MAX_VALUE / 50` ns (~2135.6 days) it wraps negative, so
`timestampNanos - epoch.landmarkNanos > rotationThresholdNanos` is true for essentially every
`dt`. `update` rotates the epoch and `continue`s; the new landmark makes `dt == 0`, which is still
`> negativeThreshold`, so it rotates again without bound.

```
DecayingSumStat(halfLife = 3650.days).update(1.0, 1_000_000_000L)   // never returns
threshold 2135d ->  9223200000000000000
threshold 2136d -> -9219224073709551616
threshold Infinity -> -50
```

Propagates to `DecayingMeanStat`, `DecayingVarianceStat` and `DecayingRateStat`, which all wrap it.
`Duration.INFINITE` gives threshold `-50`, so whether it hangs depends on uptime — observed both
outcomes across runs. A library that hangs the caller's thread is the worst failure mode here.

### 2. `AdwinStat.compress()` merges buckets into the wrong end of the next row `[V]`
`stat/change/AdwinStat.kt:109`

The invariant is stated at `:79-81`: "Front of each row is older than the back. Across rows, the
highest-k row holds the oldest buckets." `compress()` removes the two *oldest* buckets of row `k`
and does `rows[k + 1].addFirst(merged)` — the oldest end — when the merged bucket is the newest
thing in row `k+1`. It must be `addLast`.

Consequence: each row ends up reverse-chronological and higher-`k` rows hold *newer* data than
lower-`k` rows, so `bucketsOldestToNewest()` returns a scrambled order, the cut candidates are not
temporal prefixes, and `dropOldest()` discards recent data while keeping stale data.

```
row[0] front-to-back sums=[39.0, 40.0]
row[1] front-to-back sums=[75.0, 7.0, 3.0]
row[2] front-to-back sums=[42.0, 26.0]
row[3] front-to-back sums=[260.0, 196.0, 132.0]     // exactly reversed; and row 3 = values 13..36
                                                     // while row 2 = values 5..12
```

Wrong observable output — default `AdwinStat()`, 300x`0.0`, 300x`10.0`, 600x`0.0`:
```
AdwinResult(windowLength=42, mean=1.4285714285714286, variance=12.24, changesDetected=11)
```
The last 600 observations were all `0.0`, so a correct 42-wide window must read `mean=0.0`. The
window still holds six `10.0` samples from the abandoned regime. `changesDetected` inflates to 11
from bogus cuts. This is the core algorithm of the stat, not an edge case.

### 3. `SummaryStat` is missing the `requireLiveWeight` guard its two siblings have `[V]`
`stat/summary/SummaryStat.kt:78`

`MeanStat.kt:70` and `VarianceStat.kt:76` both call `requireLiveWeight` before
`totalWeights.addAndGet(weight)`. `SummaryStat` runs the identical Welford body without it, so
`weight / nextW` divides by zero.

```
update(5.0, 1L, 1.0); update(3.0, 2L, -1.0)
-> SummaryResult(totalWeights=0.0, mean=Infinity, variance=0.0, min=3.0, max=5.0)
-> any further update: mean=NaN, variance=NaN, permanently
```

This is exactly the corruption `core/Weights.kt` was written to prevent; the guard is simply absent
from one of the three stats that needs it.

### 4. `DecayingVarianceStat` dies permanently on one out-of-order timestamp `[R]`
`stat/decay/DecayingVarianceStat.kt:84`

`advanceTo()` computes `decay = exp(-alpha * (t - priorLandmark))` with no guard for
`t < priorLandmark`, so a backwards timestamp gives `decay > 1` and *inflates* `totalWeights` / `m2`,
overflowing to `Infinity` past ~1024 half-lives. The landmark also moves backwards, so nothing
recovers.

```
DecayingVarianceStat(halfLife = 1.milliseconds); update(1.0, 2e9); update(2.0, 0L)
-> DecayingVarianceResult(mean=1.0, variance=0.0, totalWeights=NaN, ...)
-> after one further in-order update: mean=NaN
```

### 5. `BloomFilterStat.merge` ignores the hasher, producing false negatives `[V]`
`stat/sketch/BloomFilterStat.kt:133`

`require(values.bits == bits && values.hashes == hashes)` — no `hasher` check, even though
`BloomFilterResult` carries a `HasherRef` and `contains()` resolves it. Merging a snapshot from a
different mixer relabels those bits with the receiver's mixer, so inserted keys report absent. This
breaks the class's single hard guarantee.

```
own contains(42)    = true
merged contains(42) = false      // hasherRef=HasherRef(name=splitmix64)
```

### 6. `CountMinSketchStat.merge` ignores the hasher, breaking the one-sided-overestimate guarantee `[V]`
`stat/sketch/CountMinSketchStat.kt:141`

Same shape: `require` covers `depth`, `width`, `seed` but not `hasher`. Counters land in cells the
receiver never probes.

```
own estimate(42)    = 100
merged estimate(42) = 0          // true count 100
```

HyperLogLog, LinearCounting and MinHash are worse in one respect — they take a `hasher` constructor
parameter but do not serialize it at all, so the mismatch cannot even be detected `[R]`:
```
HLL union of two identical 10 000-key sets under different mixers = 19620.7   (true 10000)
LinearCounting, same 500 keys under two mixers                    = 1000.9    (true 500)
MinHash identical sets, different mixers, jaccard                 = 0.0       (true 1.0)
```
`HyperLogLogStat.kt:26,119`; `LinearCountingStat.kt:24,114`; `MinHashStat.kt:24,126,58`.

## Tier 2 — wrong answers on ordinary input

### 7. The zero-weight guarantee is broken in 18 stats `[V]`
`core/Stats.kt:26` states it absolutely: "A weight of `0.0` is a no-op. The observation is not
folded in and no state changes, whatever the modality." These never look at `weight` before
mutating:

| File:line | What leaks |
|---|---|
| `stat/summary/MinStat.kt:38`, `MaxStat.kt:38` | the extremum absorbs the value |
| `stat/summary/ArgMinStat.kt:44`, `ArgMaxStat.kt:44` | value *and* timestamp |
| `stat/summary/RangeStat.kt:45` | both ends |
| `stat/summary/SummaryStat.kt:72` | `casMin`/`casMax` sit outside the `weight == 0.0` guard that protects the Welford part |
| `stat/event/ExcursionStat.kt:61` | peak/trough and their timestamps |
| `stat/event/RunLengthStat.kt:43` | run counters |
| `stat/event/RecencyStat.kt:49` | last-seen stamp |
| `stat/event/CrossingStat.kt:55` | crossing counts |
| `stat/event/SojournStat.kt:78` | state transition + accrued time |
| `stat/change/CusumStat.kt:78` | **can be driven into a false alarm** |
| `stat/change/PageHinkleyStat.kt:91` | **can be driven into a false alarm** |
| `stat/change/AdwinStat.kt:88` | window grows |
| `stat/forecast/HoltStat.kt:110` | level/trend advance |
| `stat/forecast/SeasonalSmoothingStat.kt:158` | level/trend/slot advance |
| `stat/forecast/RecursiveVarianceStat.kt:63` | variance recursion advances |

Eight values peaking at 12.0, then `update(999.0, t, 0.0)`:
```
MaxStat        max=12.0            -> max=999.0
CusumStat      cusumPositive=48.25 -> 1046.75      (with -999.0: alarmDown=true)
PageHinkley    alarmUp=false       -> alarmUp=true
Sojourn        currentState=1      -> currentState=2, 2s accrued
```
The change detectors are the severe ones: a zero weight is how a caller says "ignore this", and it
fires an alarm instead.

Separately, the `Count` spec violates the same guarantee for a *different* reason: `CountStat` is
`SumStat` wrapped in `withWeight(1.0)`, and `operation/Weights.kt:12` documents that wrapper as
"discarding caller weight". Guarantee and wrapper are in direct conflict by design — a decision, not
a forgotten guard.

Paired stats are clean. `reset` and read-purity hold across all 60 stats I could materialize.

### 8. `SummaryStat.merge` injects a `min` that was never observed `[V]`
`stat/summary/SummaryStat.kt:87-88` with `:111`

`casMin`/`casMax` run *before* the `values.totalWeights <= 0.0` early return, and `read()` sanitises
the empty sentinel to `0.0`. So merging an idle shard — the ordinary fan-in shape — drags `min` to
`0.0`; on an all-negative stream `max` is poisoned to `0.0` too.

```
empty read    = SummaryResult(totalWeights=0.0, mean=0.0, variance=0.0, min=0.0, max=0.0)
A after merge = SummaryResult(totalWeights=2.0, mean=6.0, variance=1.0, min=0.0, max=7.0)
```
`SummaryResult` is the documented feedback primary for min-max scaling, so this propagates into a
scaler. `MinStat`/`MaxStat`/`RangeStat` are correct here — they keep the infinities in `read()`.

### 9. `ExcursionStat.merge` overwrites the peak with `0.0` `[R]`
`stat/event/ExcursionStat.kt:95`, root cause `:117` (an untouched stat reads as all-zeros with no
empty flag). Same structural defect as #8.

```
before = ExcursionResult(peak=-5.0, trough=-10.0, maxExcursion=5.0, currentRecovery=5.0)
after  = ExcursionResult(peak=0.0, peakTimestampNanos=0, trough=-10.0,

Peak becomes a value never observed, its timestamp resets, and `currentRecovery` doubles while

populated stats mixes the other stat's peak with the local last value.

### 13. Positive fractional weights are silently dropped `[V]`
`stat/sketch/CountMinSketchStat.kt:132` and `stat/sketch/SpaceSavingStat.kt:190`

Both do `val w = round(weight).toLong(); if (w <= 0L) return`. These are *additive* families, so a
weight below 0.5 vanishes entirely — including `totalSeen`. Weights above 0.5 are silently rounded,
so a "weighted count" is off by up to 0.5 per update. Neither KDoc mentions rounding; the CMS KDoc
promises an "estimated **weighted** count".

```
CMS 10x update(42L, 0.4):  estimate=0 totalSeen=0 totalWeights=0.0   (true weight 4.0)
CMS 10x update(42L, 1.4):  estimate=10                                (true 14.0)
SpaceSaving 100x update(1L, 0.49): key 1L absent from heavy hitters   (true weight 49.0)
```

### 14. `CountMinSketchResult.estimate` overloads `Long.MAX_VALUE` as sentinel and datum `[V]`
`stat/sketch/CountMinSketchStat.kt:81`

Returns `0L` when the running minimum is still `Long.MAX_VALUE`, but `round(weight).toLong()`
saturates there for a huge or infinite weight.
```
update(1L, weight=1e19)        -> estimate=0
update(1L, weight=1e19) twice  -> estimate=-2
```

### 15. `RecursiveVarianceStat.merge` halves the incoming variance on a fresh stat `[R]`
`stat/forecast/RecursiveVarianceStat.kt:76`

`next = 0.5 * (current + values.variance)` with no "seen anything yet" guard, unlike
`HoltStat.kt:129` and `SeasonalSmoothingStat.kt:197`, which both adopt the remote snapshot verbatim
on an empty stat. Roll-up patterns that merge N worker snapshots into a fresh coordinator therefore
systematically halve the first contribution.
```
source: 1.9000000000000001   fresh-after-merge: 0.9500000000000001
```

### 16. `AucResult` does not equal itself `[V]`
`stat/score/AucStat.kt:49`

Hand-rolled `equals` to get `contentEquals` on its arrays, but compares `auc == other.auc` with
primitive IEEE `==`. `auc` is `NaN` for an empty or freshly reset stat.
```
a == a                       -> false
a.hashCode() == a.hashCode() -> true
setOf(a).contains(a)         -> false
```
Broken reflexivity plus an equals/hashCode contract violation, so dedup, caching and `assertEquals`
on an empty AUC result all misbehave. `hashCode` at `:58` uses `auc.hashCode()`, which *is*
NaN-stable — the two halves disagree by construction. The generated data-class `equals` would have
been correct; the fix is `auc.equals(other.auc)`. `ResultEqualityTest` never mentions Auc, which is
why it survived. ~14 other Results use the same hand-rolled pattern; I probed all of them empty and
primed and none currently expose a NaN in a compared field, so they are latent, not broken.

## Tier 3 — bad values from legal configuration

### 17. `DecayWeighting.HalfLife` accepts a sub-nanosecond half-life and yields `NaN` forever `[R]`
`stat/decay/DecayWeighting.kt:31`. `alpha = ln(2) / halfLife.inWholeNanoseconds.toDouble()` with no
validation; `inWholeNanoseconds` truncates anything under 1 ns (including `Duration.ZERO`) to `0`,
giving `alpha = Infinity`. Then `exp(alpha * 0.0) = exp(NaN) = NaN`.
```
alpha: Infinity  ->  DecayingSumResult(sum=NaN, ...)
```
Negative durations give a negative `alpha`, i.e. exponential *growth*.

### 18. `nextLogNormal` returns NaN inside its documented domain `[V]`
`math/Distributions.kt:105`. `phi = sqrt(variance + mean*mean)` underflows `mean*mean` to zero, so
`sigma = sqrt(ln(phi*phi/(mean*mean)))` is `0/0`.
```
nextLogNormal(mean=1e-162, variance=0.0)  -> NaN
nextLogNormal(mean=1e-200, variance=1e-300) -> 0.0   // non-positive draw from a positive distribution
```

### 19. `DecayingMeanStat.read()` far from the last update returns `0.0` instead of the mean `[R]`
`stat/decay/DecayingMeanStat.kt:63-69`. The premise is that the decay factor cancels in
`sumX / sumW` — true until the shared `exp(-alpha*dt)` underflows to exactly `0.0` (~1075
half-lives), when the `sumW == 0.0 -> 0.0` branch reports zero rather than the last known mean. The
ratio is recoverable from the un-decayed accumulators, so this is lost by construction rather than
inherent.
```
at t0:    mean=100.0,              totalWeights=1.0
+60s:     mean=99.99999999999936,  totalWeights=8.67e-19
+1100s:   mean=0.0,                totalWeights=0.0
```

### 20. `EwmaMeanStat` and `EwmaVarianceStat` disagree on the same underflow state `[R]`
`stat/decay/EwmaMeanStat.kt:57` vs `EwmaVarianceStat.kt:53`. `DecayWeighting.Alpha` validates
nothing, so `alpha = 0.0` makes `correction(w) == 0.0` with `w != 0.0`. Mean returns `NaN`; variance
returns `0.0`. At least one is wrong, and `NaN` from a legal constructor argument is poor —
`alpha = 0` means "no decay", whose answer is the plain running mean.
```
ewma-mean alpha0: WeightedMeanResult(totalWeights=2.0, mean=NaN)
ewma-var  alpha0: WeightedVarianceResult(totalWeights=1.0, mean=0.0, variance=0.0)
```

### 21. `CountMinSketchStat` does not validate `depth * width` against Int overflow `[V]`
`stat/sketch/CountMinSketchStat.kt:125`. `init` checks `depth > 0`, `width > 0` and power-of-two
width but not the product. `depth=16, width=1 shl 28` constructs with a zero-length array and throws
on first update: `ArrayIndexOutOfBoundsException: Index 66395917 out of bounds for length 0`.
Shapes wrapping to a *small positive* value would allocate a plausible array and silently alias rows
`[A]`.

### 22. NaN handling is inconsistent across the catalogue `[R]`
- `stat/event/CrossingStat.kt:56` — `value >= level` is false for NaN, so NaN counts as below-level
  and fabricates a down/up crossing pair. `level=5.0`, then `10.0, NaN, 10.0` gives
  `upCrossings=1, downCrossings=1`: one missing sample becomes a full alarm-and-recovery cycle.
- `stat/quantile/ThresholdBucketStat.kt:60` — the binary search walks NaN to the top bucket.
  `counts=[0,0,0,1]` for a single `update(NaN)`.
- `stat/quantile/HdrHistogramStat.kt:122` — `require(value >= 0.0)` is false for NaN, so a single NaN
  throws and takes down the caller's update path.

Meanwhile `LinearHistogramStat.kt:60`, `DDSketchStat.kt:99`, `TDigestStat.kt:349` and
`ReservoirHistogramStat.kt:216` all deliberately drop NaN. Pick one rule.

### 23. `ConfusionMatrixStat` folds a negative predicted class into class 0 `[R]`
`stat/score/ConfusionMatrixStat.kt:174`. `x.toInt()` truncates toward zero, so `-0.5 -> 0` and the
`p !in 0 until numClasses` check passes. `ConfusionMatrixStat(3).update(-0.5, 0.0)` scores an
out-of-range prediction as a correct class-0 prediction. `3.5` is correctly ignored, so only
`(-1, 0)` leaks.

### 24. `standardNormal` takes the wrong branch for `Int.MIN_VALUE` `[V]`
`math/Distributions.kt:47`. `absHz = if (hz >= 0) hz else -hz` stays negative for `Int.MIN_VALUE`,
so `absHz < ZIGGURAT_KN[iz]` is trivially true and the draw takes the inner-rectangle fast path for
layer 0 instead of the tail sampler. Probability 2^-32 per draw — a wart, not a practical failure.

### 28. `BandSeries` wrapped in `WindowedSeries` throws on every `read()` `[R]`
`operation/Band.kt:33` with `operation/WindowedStats.kt:55`

`BandSeriesStat.merge` is `error("band wrapper cannot merge BandResult; …")`, and `windowedRead`

### 29. `throttle` / `sample` never reset their phase `[R]`
`operation/Sampling.kt:58-179` and `operation/RegressionOps.kt:136-166`

None of the eight `Throttle*Stat` / `Sample*Stat` wrappers (nor the two regression ones) override

### 32. `DiagonalRegressionStat.merge` double-counts the prior `[R]`
`stat/regression/glm/DiagonalRegressionStat.kt:77`, `:79`, `:151-164`

`precision[i]` and `biasPrecision` are seeded to `priorPrecision`, and merge pools with
`pNew = p1 + p2`. An *untrained* snapshot therefore carries `precision = 1.0` rather than 0, so
merging it shrinks the trained weights toward zero and inflates the reported precision. The same
double-count applies to every merge of two real replicas.

```
start:                                w=2.4742 prec=31.0 totalW=5.0

## Confirmed clean

Verified rather than assumed, so these do not need re-checking:

- **Welford / Pébay mathematics.** `MomentsStat.update` (weighted Pébay), `MomentsStat.merge`, and
  the negative-weight downdates of `MomentsStat` and `VarianceStat` all agree with batch
  recomputation to ~1e-13. The m3/m4 merge coefficients match Pébay term by term. I hand-derived the
  single-point specialisation of the merge formula independently and it matches the update code
  exactly.
- **Quantile merge round-trips.** `LinearHistogramStat` read→merge is bit-exact including the
  underflow/overflow rows and the `binCount = 3` inexact-`binWidth` case; `HdrHistogramStat` is
  bit-exact; `DDSketchStat` and `TDigestStat` merging an empty snapshot are correct no-ops.
  DDSketch's `valueFromIndex` provably satisfies its relative-error contract at both bin edges.
- **`LinearHistogramStat.merge` layout mismatch.** Explicitly handled via `matchesLayout` with a
  re-binning fallback — good design, not a bug.
- **AUC numerics.** 1.0 for perfect separation, 0.5 for a full tie, 0.0 for inverted ranking, 1.0 at
  the bound values, 1.0 through a merge round-trip.
- **Hashing.** `SplitMixChunkHasher` chunking is correct for unaligned and empty input; the tail
  loop shifts at most 7 bytes and the unconditional final tail mix means aligned and unaligned
  inputs cannot share an exit state.
- **HyperLogLog estimator boundaries.** The `rho` derivation is correct (bucket bits and `w` bits do
  not overlap), 0 distinct gives `0.0`, 1 gives `1.0326`, and the range-switch behaves.
- **LinearCounting saturation.** Returns `POSITIVE_INFINITY` via an explicit `unset <= 0L` branch
  and `0.0` when all-clear; neither reaches `ln(0)`. Documented behaviour.
- **Other samplers.** `nextGamma` / `nextBeta` / `nextPoissonOne` / `nextNormal` guard their
  boundary and invalid parameters; the `alpha < 1` boost is floored against returning 0 and against
  `1.0 + alpha == 1.0`; `nextBeta`'s `s == 0.0` fallback is handled; `nextPoissonOne`'s loop is
  strictly decreasing.
- **`kumulant/math/Cholesky.kt`** (added in PR #44). `scale = alpha + |s[i]|` cannot reach zero: the
  `norm >= 1.0` early return guarantees `alpha = sqrt(1 - norm²) > 0`, and each iteration sets
  `alpha = scale * nrm` with both factors strictly positive. `norm <= 0.0` correctly makes a
  zero-vector downdate a no-op.
- **`CusumStat` and `PageHinkleyStat`** beyond the zero-weight issue — `Long`- and overflow-clean,
  and their approximate merges are documented as approximate.
- **Index math generally in the sketches.** Every index derivation masks with a power-of-two mask or
  uses `ushr`, so no negative-`Long` index leaks. #21 is the only broken one.
- **`reset` and read-purity** across all 60 stats materializable from a spec.
- **Paired stats** on the zero-weight contract.
- **`stream/` concurrency primitives.** Every `expect`/`actual` pair (`highWriteMode`, `spinHint`,
  `PlatformMutex` × jvm/posix/mingw/web) agrees except finding 38. Specifically ruled out with
  evidence: no `HighWrite` path can throw — `AdderMode`'s scalar `compareAndSet` does throw
  (`jvmMain/.../AdderMode.kt:60,86`), which would violate the never-throw rule, but every
  `casMax`/`casMin`/`casOr`/`compareAndSet` call site in `stat/` and `operation/` sits on
  `monotonicMode()`, `welfordMode()`, `firstWriterMode()` or a `StreamRef`, so no additive-mode cell
  is ever CAS'd. `ArrayBins`' growth CAS loop does not drop writes. `SliceRing`'s null return only
  drops writes a full window stale. `guarded`'s `check(this is PlatformMutex)` cannot be tripped —
  the lock instance is fixed at construction.
- **`requireLiveWeight`.** All three callers short-circuit `weight == 0.0` first, and with positive
  weights the total is monotone, so no legitimate interleaving — Relaxed included — can drive
  `currentTotal + weight <= 0`.
- **Spec defaults vs stat constructor defaults.** No mismatch across all 24+ spec variants carrying
  defaults, including the four `OptimizerSpec` variants.
- **`materialize` exhaustiveness.** Every `when` is `else`-less over a sealed hierarchy, no variant is
  subsumed by an earlier `is` branch, and no spec field is dropped (checked `Vectorized.skipZeros` and
  `ResampleByTimeSeries.aggregator` specifically). `DDSketch` does not expose
  `minIndexableValue`/`maxIndexableValue`, but named arguments preserve the constructor defaults — a
  missing knob, not a decode-time behaviour change.
- **Calibration.** `ReliabilityStat`, `PlattCalibratorStat`, `IsotonicCalibratorStat`: the PAV pass,
  pool fan-back, empty-bin inheritance and `calibrate` interpolation bounds are all correct.
- **Tree serialize/restore.** `snapshot()` → `merge()` round-trips predictions exactly on a grown
  3-node tree; mixed and disagreeing split-structure merges preserve total weight and keep
  probabilities summing to 1.
- **Column-major layout in the regression area.** No row/column confusion. `GaussianNaiveBayesStat`,
  `SoftmaxRegressionStat` and `HierarchicalBayesianRegression` build via `DenseMatrix.of(rows)` and
  read via `[c, i]` consistently. `MultivariateGaussian.sample` reads only `covarianceL[i, j]` for
  `j in 0..i`, i.e. the promised lower triangle. Nothing reads the strict upper triangle of a factor.
- **`InRange`** agrees with `And(Ge, Le)` — `ClosedFloatingPointRange` uses `<=`.
